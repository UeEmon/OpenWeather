# データごとの更新・取得時刻

確認日：2026-11-07（日本時間）。提供元の更新予定、データが対象とする時刻、本システムの取得時刻を区別します。固定公開時刻が未確認の場合、こちらの収集時刻を提供元の公開時刻とは表記しません。

| データ | 提供元の更新 | 本システムの取得 |
|---|---|---|
| Open-Meteo気象 | モデルごとに異なる。固定公開時刻は未確定。current.timeはデータ対象時刻 | 初回即時、その後正常取得から30分ごと |
| Open-Meteo海象 | 海洋モデルごとに異なる。固定公開時刻は未確定 | 初回即時、その後正常取得から60分ごと |
| 気象庁 海上図電文索引 | 長期フィードは毎時更新。更新の分は未指定 | 初回即時、その後毎時10分。運用上の余裕であり、配信完了の保証ではない |
| 気象庁 台風電文索引 | 同上。毎分更新の短期フィードとは別 | 同上 |
| NOAA OISST v2.1 Final | 日別確定解析、NRT版から約2週間遅れ。固定配信UTC時刻は未確認 | 初回即時、毎日18:00 UTC（翌日03:00 JST）。これは本システムの運用時刻 |

無効なソースには、未確認の取得時刻を設定しません。公開条件・製品が確認できてからSOURCES台帳へ設定します。地形PNGは提供元で随時更新、GISで閲覧した範囲を必要時に読み込みます。地図タイルの定期一括取得は行いません。

SQLiteのscheduleテーブルでデータ種別×海域ごとに次回予定と連続失敗数を保存します。再起動時にも予定を保持し、全データを無条件で再収集しません。ユーザー追加海域は未取得ジョブを登録し、10秒単位のスケジューラーで対象になります。並列取得は最大2件。グローバルな気象庁索引は海域ごとに重複取得しません。

失敗時は60秒からの指数バックオフ（最大64分、通常の取得間隔を上限）を使います。HTTP Retry-Afterの秒数指定があれば最大24時間の範囲で尊重します。前回正常データは保持します。データの取得から周期の2倍または1時間以上経つとstaleにします。最終解析の対象時刻は収集時刻とは別で、NOAAはdata_timeに表示します。

API `_meta` に `fetched_at`, `last_attempt_at`, `next_attempt_at`, `collection_interval_seconds`, `consecutive_failures`, `age_seconds`, `stale` を含めます。表示画面の「データの収集状況」には取得間隔・最終取得・次回取得予定・失敗を日本時間で表示します。

根拠：気象庁 https://xml.kishou.go.jp/xmlpull.html 、NOAAの当該データセットのsummaryとtime_coverage_end、その他はsources.jsonの出典・確認結果を参照。

GEBCO 2026は固定年次版です。全球粗格子と地点周辺格子を初回・30日ごとに取得します。原データの毎日の更新を意味しません。新版への切替には製品・再利用条件の再確認が必要です。スケジュール設定ではこのソースに30日以上・365日以下の範囲を適用します。
